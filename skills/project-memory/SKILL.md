# 项目记忆库（project-memory）

AI 的每个新对话都是失忆的。这个 skill 让项目自己带着记忆：一个放在项目里的 `MEMORY.md`，**开工先读，完工必写**。

## 开工：先读再动手

1. 找记忆库：项目根目录的 `MEMORY.md`；没有就找 `PLAYBOOK.md`、`运营手册.md`、`CLAUDE.md`、`AGENTS.md`。
2. **完整读一遍再做任何事**。按里面的“规矩”和“最新决策”行事，不要按自己的默认习惯来。
3. 记忆库和用户刚说的话冲突时，**以用户最新的话为准**，并马上把记忆库改掉（见“写回”）。
4. 没有记忆库、而这是一个会持续多天的项目：先用 `scripts/memory.py init` 建一个，再开工。

## 记忆库的结构

固定 7 节，顺序不变，方便任何人 30 秒内找到东西（模板见 `references/template.md`）：

| 节 | 写什么 |
|---|---|
| 0 规矩与偏好 | 用户明确说过的工作方式：谁拍板、什么要审批、沟通习惯、时区 |
| 1 机器与权限 | 有哪些电脑/服务器、怎么连、各能做什么、哪些操作被限制 |
| 2 账号与资源 | 账号、域名、仓库、API 服务**在哪**（只写位置，**绝不写密码和 key 本身**） |
| 3 决策日志 | `日期 · 决策 · 原因`，最新的在上面；被推翻的标 ~~删除线~~ 并写新决策 |
| 4 进度 | 一张表：事项 / 状态 / 位置 |
| 5 已知坑 | 踩过的坑和解法，一条一行 |
| 6 下一步 | 有序清单，下一个接手的人照着做 |

## 写回：什么时候写、写什么

**这几种时刻必须写回**，不要等对话结束（对话可能随时中断）：
- 用户做了决定、改了规矩、给了新资源或新权限
- 完成一个里程碑、上线了东西、换了方案
- 踩到坑并找到解法
- 发现记忆库里有过时的内容

**写什么**：
- 用户说过的事实和决定，用接近原话的方式写
- 东西放在哪里（路径、URL、服务名）
- 结论和原因，不写过程流水账

**不写什么**：
- 密码、API key、token、cookie、验证码。最多写“key 在 4090 的 ~/.xxx_key”
- 临时状态（“正在下载”“刚才报错了”），除非它会影响下一个人
- 自己的猜测。不确定的写成“待确认：……”

## 保持好用

- **控制长度**：MEMORY.md 尽量不超过 300 行。旧的决策日志、完成的进度挪进 `memory/archive-YYYY-MM.md`，主文件只留一行指针。
- **多份副本**：如果记忆库在多台机器上各有一份，每次写回后同步，并在文件头写“最后更新：日期”，以日期新的为准。
- **交接测试**：写完问自己——一个全新的对话只读这份文件，能不能在 5 分钟内接着干？不能就补。

## 自带工具

```bash
python3 scripts/memory.py init  [目录]              # 按模板新建 MEMORY.md
python3 scripts/memory.py check [MEMORY.md]         # 检查：缺节、疑似密钥、过长、日期太旧
python3 scripts/memory.py decide [MEMORY.md] "决策" "原因"   # 往决策日志顶部加一条带日期的记录
```

`check` 发现疑似密钥会报错并指出行号。**提交、分享或公开记忆库之前一定先跑一遍。**
